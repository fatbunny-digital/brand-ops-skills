# 推广实验与结果判断

## 实验前

固定客户、市场、SKU/规格、报价、目标页面、库存和活动期限。确认目标是付费订单、贡献、新客户还是明确的合格询盘；这些指标不混为一种转化。

检查现有购买路径与测量记录。平台显示收到事件，不证明实际付款、正确去重或广告归因。没有可靠付款证据时，可以继续制作和规划，不将测试事件当收入，也不接手技术埋点。

## 最小实验记录

| 字段 | 内容 |
| --- | --- |
| 假设 | 哪类客户因什么理由更愿意购买，依据是什么 |
| 改动 | 创意概念、报价或页面的主要差异 |
| 成功指标 | 业务指标及必要的前置观察指标 |
| 边界 | 市场、预算、期间、库存、可接受损失和已授权范围 |
| 复盘条件 | 何时或达到什么信息量复核，哪些情况应暂停 |
| 结果 | 数据、限制、继续/调整/停止及下一步 |

不要只换背景颜色就宣称测试了多个购买动机。自然内容和广告都先记录基线；无法做可靠对照时，用明确限制的前后观察，不声称因果。

## 分析顺序

1. 核对日期、时区、币种、归因窗口、订单与收入定义、平台延迟。
2. 排除数据缺失、付款失败、页面不可用、错规格、缺货、报价过期等运营阻碍。
3. 将展示、点击、到站、加购、结账、付费订单分开，说明数据分母是否一致。
4. 根据实际贡献和目标评估花费。不能把 Meta、Google 等各自认领的订单或收入相加当作实际销售。
5. 小样本、一天数据、少量转化或尚未成熟的归因只支持有限结论。点击便宜不能单独证明值得加预算。

## 动作

优先解决影响当前购买路径的问题，再决定更换概念、修改报价或调整预算。每项动作给出依据和下次判断条件。真实执行后读回平台状态；有额度、日期或账户边界时不得擅自扩大。
