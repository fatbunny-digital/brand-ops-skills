# 品牌经营工具箱 · Brand Ops Skills

**给品牌老板和运营人员的五个中文 AI Skills：市场洞察、商品企划、内容推广、客户经营、经营复盘。**

把品牌资料、商品、政策和报表交给助手，用日常语言完成研究、活动、文案、客户跟进与经营分析。适合经营实物商品的消费品牌，也适合为多个品牌提供运营服务的团队。

由 [Fatbunny Digital](https://github.com/fatbunny-digital) 维护，采用 [MIT 开源许可](LICENSE)，可用于自己的品牌、客户交付和商业项目。

这是一套工作方法与可用模板。基础使用不需要编程、搭建数据库或购买指定软件；AI 助手本身及可选平台工具的费用由各自服务决定。实际发布、发信、广告投放或订单操作取决于助手可用的工具和你授予的权限。

## 五个 skill 怎么选

| 中文名称 | 内部标识 | 你可以让它做什么 | 常见交付 |
| --- | --- | --- | --- |
| [市场洞察](skills/market-insights/SKILL.md) | `market-insights` | 找客户需求、分析评价、研究竞品、梳理定位 | 品牌简报、客户洞察、竞品对比、机会与依据 |
| [商品企划](skills/product-planning/SKILL.md) | `product-planning` | 写商品资料、确定主推组合、测算优惠、规划库存 | 商品成稿、活动方案、利润测算、库存建议 |
| [内容推广](skills/content-marketing/SKILL.md) | `content-marketing` | 做社媒、博客、图片视频创意、广告计划与优化 | 内容日历、成稿、脚本、素材简报、推广实验 |
| [客户经营](skills/customer-care/SKILL.md) | `customer-care` | 回复客户、跟进订单、处理售后、安排复购 | 回复成稿、异常清单、FAQ、分群与跟进方案 |
| [经营复盘](skills/business-review/SKILL.md) | `business-review` | 看销售与贡献、复盘活动、判断优先事项 | 经营报告、问题依据、下一阶段行动清单 |

五个能力可以单独用，也可以衔接：

> 看懂客户 → 确定商品和活动 → 做内容推广 → 承接客户与订单 → 复盘下一步。

中文是展示名称，英文用于安装和明确调用。`agents/openai.yaml` 配置中文展示；其他助手是否显示中文取决于其界面支持。

## 适用范围

本工具箱处理现有工具内的运营工作：品牌与市场研究、商品内容、促销、内容与广告、客服履约、客户复购和经营报表。

网站开发、代码修改、接口集成、埋点安装、基础设施、技术 SEO 修复和自动化系统搭建不在范围内。发现技术阻碍时，助手应整理现象、业务影响和交接事项。

例如：可以写商品页正文、检查优惠条件、在已授权后台更新内容；如果需要新增结账功能，则交接开发。

## 十分钟完成第一次使用

还没有品牌资料？先用本仓库的虚构品牌练一次，无需连接任何真实账户。

1. 完成下面任一安装方式，或者先直接向助手提供对应 `SKILL.md` 及其引用资料。
2. 下载 [青禾织物练习目录](examples/demo-brand)，让助手读取其中的品牌简报、两周汇总和渠道汇总。如果助手不能读本地目录，上传这些文件。
3. 把下面这段话发给助手。

```text
使用 $business-review（经营复盘）。

读取 examples/demo-brand/brand-brief.md、weekly-summary.csv 和
channel-summary.csv；这些是虚构离线练习数据。

对比两周的订单、收入、客单价、广告前后贡献和渠道表现。
先告诉我经营变化，再给下周最应该做的三件事。
说明不能根据现有资料判断什么。不要访问账户或执行外部操作。
```

文件上传时把路径改为实际文件名。助手应发现：订单和收入增长，但广告后贡献由 **1476 元下降到 1098 元**。详细计算见 [练习步骤与参考结果](examples/demo-brand/walkthrough.md)。

这能验证它是否理解口径、会计算、能提出有依据的动作。模型用词不必一致；不能因为句子写得漂亮就忽略计算或事实错误。

## 安装教程

### 方式一：让 Codex 帮你安装

适合已经在使用 Codex、且当前环境提供 `skill-installer` 的用户。在 Codex 对话中发送：

```text
使用 $skill-installer，从公开 GitHub 仓库
fatbunny-digital/brand-ops-skills 安装以下五个 skill：

skills/market-insights
skills/product-planning
skills/content-marketing
skills/customer-care
skills/business-review

如果已有同名 skill，先列出已有版本和安装位置，不覆盖我的自定义内容。
```

安装完成后在下一轮对话使用。若列表没出现，重新打开会话或重启助手，再检查实际安装目录。

这里只安装技能文件，不安装广告、邮件、店铺连接器，也不代表已授予任何账户权限。本仓库未发布到插件市场，不要把 GitHub 地址当成已审核上架的插件。

### 方式二：下载后手动安装到一个品牌工作区

适合不想使用命令行，或只想在某个品牌项目中使用的人。

1. 在仓库页面点击 **Code → Download ZIP**，解压。
2. 新建一个自己的品牌工作目录，例如 `my-brand`。客户资料放这里，不放回公共仓库。
3. 在该目录创建 `.agents/skills/`，将下载目录 `skills/` 下的五个完整文件夹复制进去。
4. 让 Codex 打开这个品牌工作目录。目录结构应如下所示。

```text
my-brand/
├── .agents/
│   └── skills/
│       ├── market-insights/
│       │   ├── SKILL.md
│       │   └── agents/openai.yaml
│       ├── product-planning/
│       │   ├── SKILL.md
│       │   ├── agents/openai.yaml
│       │   └── references/economics.md
│       ├── content-marketing/
│       │   ├── SKILL.md
│       │   ├── agents/openai.yaml
│       │   └── references/experiments.md
│       ├── customer-care/
│       │   ├── SKILL.md
│       │   └── agents/openai.yaml
│       └── business-review/
│           ├── SKILL.md
│           ├── agents/openai.yaml
│           └── references/metrics.md
├── brand-brief.md
├── data/
└── outputs/
```

复制整个文件夹，保留 `references/` 和 `agents/`。只复制 `SKILL.md` 会丢失部分计算说明与中文展示配置。文件管理器可能需要打开“显示隐藏文件”才能看到 `.agents`。

如果你习惯 Git，也可以先下载源仓库：

```bash
git clone https://github.com/fatbunny-digital/brand-ops-skills.git
```

然后按上述步骤复制到实际品牌工作区。克隆后留在源仓库根目录，并不会自动把其 `skills/` 注册为项目技能目录。

本节的项目目录和调用方式依据 [OpenAI 官方 Skills 文档](https://learn.chatgpt.com/docs/build-skills)。不同版本的桌面端、CLI 和 IDE 扩展可能有不同入口；以当前客户端和安装器返回的位置为准。

### 方式三：其他 AI 助手或暂不安装

这些文件使用 `SKILL.md` 组织工作流。若你的助手支持相同技能格式，按它自己的安装说明导入五个文件夹；本仓库不声称已经验证所有客户端。

如果没有技能安装功能，可以直接给助手 `SKILL.md` 和其中用到的引用文件，并说：

```text
请阅读我提供的“商品企划”SKILL.md 和 economics.md，
按这些方法完成本次任务。品牌资料是……
本次只做方案，不修改线上价格。
```

这属于手工提供工作说明，不会自动注册技能，也不保证助手具有联网、文件或平台操作能力。

### 检查是否装对

向助手发送：

```text
请检查是否能发现 market-insights、product-planning、
content-marketing、customer-care、business-review。
列出实际可读的 skill 路径，以及各自的中文名称。
不要只根据我给的名称回答。
```

正确结果应能定位五个 `SKILL.md`。若有同名条目，先确认来自哪个目录，避免旧版本和新版本同时使用。

## 准备品牌资料

### 最少提供什么

开始一项具体工作，通常只需要品牌/店铺、商品、目标客户、本次目标和相关限制。已有资料先用，未知写“待确认”。

例如：

```text
品牌：青禾织物（练习品牌）。
商品：棉质毛巾和双条礼盒，规格见附件。
市场：中国大陆，文案用中文。
目标：补齐礼盒商品说明，准备三条社媒内容。
限制：不使用没有证明的功效，不发布，不打折。
```

没有成本也能做客户研究和文案；没有订阅状态不能直接群发；没有可靠订单历史就不能判断真实复购表现。

### 建立一份共用品牌档案

复制 [品牌运营档案模板](templates/brand-brief.md) 到自己的私有工作区，命名为 `brand-brief.md`。让助手先帮你整理：

```text
读取我提供的商品、品牌介绍和配送政策，
按 brand-brief.md 模板整理运营档案。
每个重要结论保留来源和日期。
区分事实、我已确认的决策和你的假设；未知写待确认。
先给我可审阅的版本，不把假设当成品牌事实。
```

同一份档案供五个 skill 使用。新会话明确提供文件或位置；不要假设换了会话、项目或客户后，助手自动记得原资料。

### 按任务补资料

| 任务 | 有帮助的资料 | 缺少时怎样继续 |
| --- | --- | --- |
| 客户研究 | 评价、客服主题、访谈、已知竞品、目标市场 | 做已有样本分析，说明覆盖范围 |
| 商品与活动 | SKU、价格、成本、库存、交期、政策 | 可以写文案；利润和补货结论保留缺口 |
| 内容与广告 | 品牌语气、商品图、报价、渠道、历史表现、预算 | 先做草稿，不声称已经发布或盈利 |
| 客户跟进 | 脱敏订单状态、消息、政策、订阅与退订 | 做处理方案；资料不全不承诺退款或营销发送 |
| 经营复盘 | 同口径销售、退款、成本、广告、库存报表 | 先分析已有部分，不硬算缺数据的指标 |

CSV、表格、文档和清楚的文字都可使用，不要求换电商平台。文件需要被助手实际读取；只有截图时，复杂金额应核对可读表格。

## 五个 skill 的详细用法

### 1. 市场洞察：决定对谁说什么

适合新品牌定位、进入新市场、主推商品调整和评价分析。

```text
使用 $market-insights（市场洞察）。
读取品牌简报和附件中的客户评价，分析礼赠客户的购买动机与顾虑。
按实际样本记录主题和频次，给我三个值得验证的商品表达方向。
把客户原话脱敏，区分事实和假设。
```

有联网能力时可以进一步要求：

```text
针对我的目标市场寻找直接竞争对手，区分替代方案和表达参考。
比较相近规格、价格条件、主张、证明和购买路径。
附来源、观察日期和纳入理由；查不到的信息保持未知。
不要把对手的广告数量或投放时间写成盈利证据。
```

**应拿到：** 有依据的客户/竞争结论、商品可支持的差异、事实缺口和具体测试机会。对手销量、广告预算或 ROAS 不应被凭空补出。

### 2. 商品企划：决定卖什么、怎么卖

适合商品上新、页面内容、主推组合、节日活动、优惠和库存安排。

```text
使用 $product-planning（商品企划）。
读取品牌简报、SKU 表和当前库存，为下个月准备两个礼赠活动方案。
比较原价搭配和套装优惠；逐项计算商品、支付、包装、运费及贡献。
写清适用商品、优惠条件、时间、库存限制和运营执行步骤。
只做方案，不改价、不采购。
```

只要商品文案时，可以更短：

```text
使用 $product-planning，依据这份真实商品资料，
给我后台可直接使用的标题、短描述、正文和五条FAQ。
保留规格与退换条件，不添加资料里没有的认证或功效。
```

**应拿到：** 具体成稿或可执行方案；金额可核对、库存和交期有依据。广告前贡献不应被写成完整净利润。

### 3. 内容推广：把活动变成内容与推广动作

覆盖自然内容、社媒、博客、素材和广告。可以只做一条文案，也能组织一周推广。

```text
使用 $content-marketing（内容推广）。
依据已确认的商品活动，准备下周的内容日历：
三条社媒成稿、一篇购买指南、一个20—30秒短视频脚本。
逐条写清目标客户、商品事实、画面/镜头、CTA和落地页。
没有素材的地方给拍摄清单。只制作，不发布。
```

广告分析例子：

```text
使用 $content-marketing，读取近两周广告导出与同期间订单汇总。
先核对日期、币种、归因和收入定义，再判断问题更可能在哪个环节。
给出下一轮素材测试与预算建议，说明样本限制。
不把多个平台认领的订单相加，不修改预算。
```

**应拿到：** 能使用的内容、素材简报或推广方案，以及有依据的优化动作。图片/视频是否能直接生成取决于当前工具；只交付脚本时不能称为已完成成片。

已有 `meta-ads` 等专项 skill 时可按需调用；本仓库没有将它作为安装依赖，也不会自动替你安装它。

### 4. 客户经营：解决问题，安排合适的后续跟进

适合单个客户回复、物流异常、退换货、FAQ 和已有客户复购。

```text
使用 $customer-care（客户经营）。
根据附件中的脱敏订单、客户消息与退换货政策，
整理待处理问题和优先级，并写好每位客户的回复。
区分客户说法、已核实状态和待确认信息；不要承诺未确认的到货时间。
只生成草稿，不发送、不退款。
```

复购例子：

```text
使用 $customer-care，设计购后护理与礼赠交叉销售方案。
明确人群、触发时间、频次、排除条件、文案与停止条件。
营销只纳入订阅状态已确认且无未解决售后问题的客户。
没有复购历史时用简单分群，不预测客户终身价值。
```

**应拿到：** 可用回复或跟进方案、具体筛选规则和待处理清单。订单通知与营销必须区分；真实发送、退款和补发沿用用户明确授权。

### 5. 经营复盘：把报表变成下一步

适合每周/月、活动结束、销售下降或预算调整前。

```text
使用 $business-review（经营复盘）。
读取品牌简报与本周、上周的订单、退款、成本、广告和库存导出。
先核对日期、币种及指标定义。
告诉我：发生了什么、哪些原因只是推测、下周先做什么。
行动写到具体商品或环节，附负责人建议、期限和复核指标。
缺数据就明确缺口，不把贡献写成净利润。
```

可以指定使用 [周复盘模板](templates/weekly-review.md)，也可以只要一页结论。复盘不意味着必须做仪表盘或数据系统。

**应拿到：** 可核对的指标、判断边界和有顺序的行动。没有会话数据就不能硬算转化率，没有可比客户观察窗口就不能声称复购提升。

## 完整练习：准备一次礼赠推广

练习资料：[青禾织物](examples/demo-brand/brand-brief.md)。全流程只做离线工作。

| 步骤 | 使用 skill | 本步任务 | 下一步使用的结果 |
| --- | --- | --- | --- |
| 1 | 市场洞察 | 读取五条合成反馈，找礼赠顾虑 | 数量/规格、护理与送礼时间问题 |
| 2 | 商品企划 | 补齐商品表达，测算毛巾九折，检查库存 | 商品成稿、报价测算、库存风险 |
| 3 | 内容推广 | 准备三条社媒和拍摄说明 | 可用内容与待补真实素材 |
| 4 | 客户经营 | 按条件筛选合成客户，准备邮件和回复 | 明确对象、排除条件与草稿 |
| 5 | 经营复盘 | 对比两周销售与渠道报表 | 收入/贡献结论和下周行动 |

每一步的复制提示词和可核对数字见 [完整练习教程](examples/demo-brand/walkthrough.md)。不需要让助手一次加载所有 skill；上一步的有用成果交给下一步即可。

实际品牌可以采用这样的节奏：周初复盘和选重点，按需要做研究与商品调整，准备内容和客户跟进，期间处理订单与库存，周末核对结果。根据团队和商品周期调整，不要求每天使用全部五个。

## 怎样提出一个有效任务

说明五件事通常就够：**背景、目标、资料、限制、想要的交付物。** 可复制 [单次任务模板](templates/task-brief.md)。

“帮我做营销”范围太大。可以改成：

```text
我们卖家居礼盒，主要面向中国大陆的礼赠客户。
本周先完善礼盒商品表达；附件有规格和五条客户反馈。
给我商品页可用的短描述、三条FAQ和一条社媒成稿。
不添加认证或健康功效，不打折、不发布。
```

如果资料少，让助手先完成能完成的部分，集中列出真正影响决策的问题。不要为了填满模板编造数字。

## 从草稿到现有工具内执行

基础使用可以停留在研究、分析、成稿与操作清单。需要操作时，清楚说明平台、账户、动作和范围；已有有效授权应继续沿用。

例如，先要求准备邮件预览和筛选人数，审阅后明确授权向哪些已订阅客户发送；或对具体广告计划明确账户、市场、期间、预算及上限。平均日预算是否允许单日超出，需要以平台当前规则为准。

助手只能报告实际完成的阶段：**已准备 → 已应用/提交 → 平台接收/发布 → 业务结果已验证**。邮件接收不代表送达，广告发布不代表出量，购买事件接收不代表真实付款。

没有连接器或登录状态时，它应交付可手工执行的成果。不会因为安装了 skill 就拥有你的店铺、广告账户或客户名单。

## 多个品牌与客户交付

每个品牌使用独立资料目录、会话或项目：

```text
brands/
├── brand-a/
│   ├── brand-brief.md
│   ├── data/
│   └── outputs/
└── brand-b/
    ├── brand-brief.md
    ├── data/
    └── outputs/
```

通用 skill 可以共用；品牌定位、价格、政策、客户、账户和授权不共用。接手前确认本次品牌和市场，避免把 A 品牌优惠或资料带给 B 品牌。

交付新客户时：

1. 分享本仓库和安装方式。
2. 帮客户建立自己的品牌档案，收集必要的脱敏样本。
3. 选一个真实小任务走通，例如补商品说明或做一页周报。
4. 核对事实、金额、品牌语气与操作状态。
5. 保留成果和已确认决定，再扩大使用范围。

MIT 许可允许商业使用和修改；分发时保留许可与版权声明。不要把客户导出、密钥、内部报表、真实客户截图或未获许可的素材提交到公共仓库。模板中的占位说明在私有副本填写，练习数据不能混进真实报表。

## 更新与卸载

### 更新

先记录自己修改过的 skill，备份到私有位置，再下载新版本比较变化。复制安装是独立副本，源仓库更新不会自动更新已安装文件。

如果使用 Git 保存源文件，工作区干净时可以在源仓库运行：

```bash
git pull --ff-only
```

随后将新 skill 文件夹更新到实际安装位置。遇到同名目录先比较，避免直接覆盖自己的修改；品牌资料始终独立保留。下载某次提交的固定版本可提高团队复现性，本仓库不要求自动更新。

### 卸载

在实际安装目录找到本仓库的五个 skill 文件夹，确认路径后移除需要卸载的项。重新打开助手检查列表。不要删除整个技能目录，也不要删除品牌数据与成果。

## 常见问题

**只能给一个网站用吗？**

可以给不同品牌用。方法通用，品牌资料独立；不绑定本仓库维护者的 CMS 或店铺。

**一定要连接广告和店铺吗？**

不需要。用脱敏导出就能完成许多分析和草稿。实际后台操作需要相应工具、访问能力和用户授权。

**为什么看到的是英文名字？**

内部标识是英文，中文展示写在 `agents/openai.yaml`；不同客户端可能只展示内部名称。可以用英文标识明确调用，用中文提出需求。

**助手说没找到 skill？**

确认打开的是正确品牌目录、文件夹没有多套一层、存在 `SKILL.md`，且当前客户端支持该安装位置。请它列出实际读取路径，必要时重启；临时也可手工提供技能文件及引用。

**已有同名 skill 怎么办？**

先看来源与修改，选择保留或合并。不要直接覆盖；同名技能可能同时显示，不一定会合并。仓库只提供五个标识，没有更改你已有技能的权限。

**可以只装一个吗？**

可以。每个 skill 的必要引用都在自身目录，不强依赖另外四个。品牌档案是可选工作资料，不是安装依赖。

**品牌想用英文或其他语言呢？**

告诉助手目标市场、语言和语气。中文说明不会强制所有客户文案用中文，商品与政策事实仍需保持一致。

**表格算错、引用不实怎么办？**

保留原始资料，请助手指出具体来源、计算口径并重算；用练习教程中的数字检查基本行为。未经核实的结果不进入活动或对外文案。

**能自动群发、退款或加预算吗？**

只有在工具支持且用户明确授权范围内执行。单纯做分析或起草不会授权这些操作；没有工具时交付手工清单。

**是否包含技术 SEO、埋点和开发？**

不包含。内容推广负责内容与运营表达，经营复盘负责现有资料分析；技术问题仅整理交接。
